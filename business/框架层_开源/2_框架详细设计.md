## 二、框架表结构（PG DDL，SQLite 档按降级矩阵替换）

### 2.1 tasks（任务根）

```sql
CREATE TABLE tasks (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id         uuid NOT NULL REFERENCES tenants(id),
  pipeline          text NOT NULL,
  pipeline_version  int  NOT NULL,             -- 创建时解析并绑定快照
  priority          smallint NOT NULL DEFAULT 30, -- 10 交互读/20 落袋写/30 治理/40 常规/50 批量
  status            text NOT NULL DEFAULT 'pending'
                    CHECK (status IN ('pending','running','waiting','succeeded','failed','partial','canceled')),
  idempotency_key   text,
  params            jsonb NOT NULL DEFAULT '{}',   -- L4 实例参数
  config_snapshot   jsonb NOT NULL,                -- 版本快照：pipeline+registry+contract 版本集合
  deadline_at       timestamptz,                    -- 任务级总闸
  created_at        timestamptz NOT NULL DEFAULT now(),
  updated_at        timestamptz NOT NULL DEFAULT now(),
  UNIQUE (tenant_id, idempotency_key)
);
CREATE INDEX idx_tasks_dispatch ON tasks (tenant_id, priority, status) WHERE status IN ('pending','running','waiting');
```

### 2.2 task_steps（节点/检查点 = 任务游标）

```sql
CREATE TABLE task_steps (
  id             bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  task_id        uuid NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  node_id        text NOT NULL,                   -- 图内唯一
  node_type      text NOT NULL CHECK (node_type IN ('step','fork','loop','switch','wait','subflow')),
  step_name      text,  step_version int,         -- step 节点绑定
  status         text NOT NULL DEFAULT 'ready'
                 CHECK (status IN ('ready','running','waiting','succeeded','failed','skipped','abstained')),
  attempts       int NOT NULL DEFAULT 0,
  lease_owner    text, lease_expires_at timestamptz,
  join_policy    text CHECK (join_policy IN ('all','quorum','any')),  -- fork/join
  parent_ref     bigint,                          -- fork 子步骤 → 父 join 节点
  input_ref      text, output_ref text,           -- 检查点文档（jsonb 存引用或内联小文档）
  iteration      int, loop_key text,              -- loop 轮次/批键（fork 物化子任务）
  abstain_reason text,                            -- 显式弃权原因码（A15，禁空串）
  error          jsonb,
  started_at timestamptz, finished_at timestamptz,
  UNIQUE (task_id, node_id, COALESCE(loop_key,''), COALESCE(iteration::text,''))
);
CREATE INDEX idx_steps_ready ON task_steps (status, lease_expires_at) WHERE status = 'ready';
CREATE INDEX idx_steps_lease ON task_steps (lease_expires_at) WHERE status = 'running';
```

## 三、统一签名与处理容器运行时（A9）

### 3.1 统一签名（唯一方法形态）

```python
@unified_method(registry="extract.deep", version=3)
def deep_extract(input: dict, output: dict, context: dict, tenant: dict, metrics: dict) -> bool:
    # ③ 操作段：只写业务逻辑；①②④⑤ 由容器按注册配置执行
    atoms = propose_atoms(input["segments"], input["signals"])
    output["atoms"] = atoms
    return True
```

- 五参**全 map**；返回 `boolean`（成功/失败路径）；框架按 component_registry.container 配置执行五段；
- 判定型步骤约定：output 必带 `confidence: float`（0–1）与 `abstain_reason?: str`（契约断言强制，A15/软信号 A14-⑤）。

### 3.2 五段执行 runner（伪代码，原子化）

```python
def run_step(reg, input_map, context, tenant, metrics) -> dict:      # container/runner.py
    values = extract_by_mappings(reg.container.input, input_map, context)   # ①提取(required/缺省/断言)
    obj = build_object(reg.container.bind, values)                          # ②封装(强类型只在容器内)
    ok = call_operation(reg, obj, context, tenant, metrics)                 # ③操作(业务代码)
    out = flatten_by_mappings(reg.container.output, obj)                    # ④拍平写回 output map
    out = enforce_soft_signal(out, reg) if is_judgment_step(reg) else out   # ④'判定型补 confidence
    return out
```

失败路径交 policy 引擎（§五），不进业务代码。

## 四、图引擎（A2/A12）

### 4.1 任务/节点状态机

```
任务:  pending → running → (waiting ⇄ running)* → succeeded | failed | partial | canceled
节点:  ready → running → succeeded | failed | abstained | skipped
              └→ waiting（wait 节点/subflow/join 未满）→ ready（事件到达）
```

不变式（A7 四条）：① 节点完成 = 原子提交（输出文档+状态推进+后继激活同事务）；② 幂等重放；③ 优雅退出（SIGTERM 停领新活、释放租约）；④ 配置快照绑定（在途任务永远执行绑定版本）。

### 4.2 就绪派发（SKIP LOCKED，worker 拉模式）

```sql
WITH cand AS (
  SELECT s.id FROM task_steps s JOIN tasks t ON t.id = s.task_id
  WHERE s.status = 'ready'
    AND (s.lease_expires_at IS NULL OR s.lease_expires_at < now())
    AND t.status IN ('pending','running','waiting')
  ORDER BY t.priority ASC, s.id
  FOR UPDATE OF s SKIP LOCKED
  LIMIT $1
)
UPDATE task_steps s SET status='running', lease_owner=$2,
       lease_expires_at = now() + interval '90 seconds', attempts = s.attempts + 1
FROM cand WHERE s.id = cand.id
RETURNING s.task_id, s.node_id, s.step_name, s.step_version;
```

- worker 心跳续租（默认 30s 间隔 / 90s 租期）；过期 → 他人可重置 ready 重派；
- **调度顺序 = 优先级 ASC（10 最高）**；同任务节点间仅受依赖约束（fork 并行）。

### 4.3 推进与条件边

- step 完成 → 同事务写检查点并激活后继：无条件边直接置 ready；条件边按 json-logic 求值（输入 = 前驱 output map + context），**全未激活 → default 分支**；
- **default 约束（编译期⑤）**：default 边与兜底路径的目标必须是 `review/dead_letter/abstain` 类节点，直连成功终态 → 发布拒绝；
- fork：from 列表路径物化 N 个子 task_steps（iteration+loop_key 批键），join 按 all/quorum/any + 超时（超时 → PARTIAL + 复核队列）；
- loop：每轮完成后求值 until（可读写 output 累计区），轮间提交检查点（崩溃从第 k 轮续跑），max_iterations 耗尽按异常策略；
- wait：挂起 + 事件名 + 签名校验（HMAC）+ 超时 → 异常策略；
- subflow：实例化子 pipeline（独立 tasks 行 + parent_ref），父 wait 至子终态。

### 4.4 调用缓存（recovery/cache.py）

键 = `(node_id, input_hash, prompt_version)`；命中直接回填 output、置 succeeded（不计费重跑）；外部调用统一经 `InferenceProvider` 打点写入。

## 五、异常策略引擎（A15 落点）

### 5.1 错误类型 × 处置（策略即数据，步骤级默认/节点级覆盖）

| 错误类型 | action | 参数 | 语义 |
|---|---|---|---|
| ContractViolation | review | queue | 转复核队列，不重试 |
| TransientError | retry | max, backoff=exp | 重试优先于新任务准入 |
| DependencyError | fallback | to: step@version | 备用实现（经防腐层声明） |
| BusinessReject | reply | value | fallback 值写 output，流程可继续 |
| **Undecidable（abstain）** | **abstain** | reason_code | **一等结论**：置节点 `abstained` + 写复核队列 + 原因码必填（禁空/禁"unknown"） |
| "\*"（兜底） | dead_letter | alert: true | 死信 + 告警 |

**禁配**（CI 拒收）：任何步骤以 `reply`/`retry` 处置 `Undecidable`；default 直进成功终态；`abstain_reason` 缺省。

### 5.2 abstain 的数据路径

```
业务代码 raise Undecidable("entity_merge_conflict", detail=...) 
  → policy: task_steps.status='abstained', abstain_reason=code
  → pipeline_review_queue 插行（引用+原因+重试状态）
  → metrics.abstain_total{step,reason} +1
  → 后继按图约束不激活（或激活至 review 汇聚节点）
```

## 七、Store 接口族（A10，9 槽位 Protocol 摘要）

```python
class DataStore(Protocol):
    def execute(self, sql: str, params: dict, *, tenant: TenantCtx) -> list[dict]: ...
    def transaction(self) -> AbstractContextManager: ...          # RLS SET/RESET 挂钩
class VectorStore(Protocol):
    def upsert(self, ns: str, vecs: list[tuple[str, list[float]]]) -> None: ...
    def search(self, ns: str, q: list[float], k: int, flt: dict | None = None) -> list[Hit]: ...
class FullTextStore(Protocol):  def index/update/search(...) 
class GraphStore(Protocol):     def neighbors/upsert_edges/walk(...)
class TaskQueue(Protocol):      def enqueue/deploy/poll(...)    # 框架内默认 PG SKIP LOCKED
class CacheStore(Protocol):     def get/set/delete/invalidate_tag(...)
class LockStore(Protocol):      def acquire(key, ttl) -> Handle | None
class ObjectStore(Protocol):    def put/get/presign(...)
class PubSubStore(Protocol):    def publish/subscribe(...)
```

降级矩阵（缺失 → 顶替）：Redis→内存 LRU+TTL；PG TaskQueue→SQLite CAS 抢占→内存队列；PG advisory→文件锁→内存锁；pgvector→sqlite-vec→内存向量；pg_notify→进程内事件总线+扫描兜底。**DataStore/FullTextStore/GraphStore/ObjectStore 为必需槽位**（无降级）。

## 九、租户隔离与安全（security/）

- **上下文贯穿**：`TenantCtx(tenant_id, domain_id?, actor, trace_id)` 存 contextvar，HTTP 中间件/任务参数双入口注入；日志仅作标签；
- **RLS 生命周期**：连接 checkout 时 `SET LOCAL app.tenant_id = $tid`；return 时 `RESET`——由 DataStore.transaction() 强制，业务不可绕过；SQLite 档应用层过滤 + **单租户强制声明**；
- **密钥**：DEK（按租户，字段级 AES-GCM，key_version 列）+ KEK（Vault/KMS）；轮转：读按 version 解密、写用当前 version，惰性重加密后台批量；
- **审计**：框架动作（受理/裁决放行引用/导出/审计查询本身）写 audit_log；月分区封存 + prev_hash 链；审计访问写二级流。

## 十二、组件升级（registry/upgrade.py）

```
新版本注册(name, v+1) → CI 门禁(合同测试+样本干跑) → active 发布
  → 新任务解析绑定快照 → 在途任务不受影响 → 监控对比 → 旧版本 deprecated → 在途归零退役
```

灰度：version_hint 按租户/百分比路由；契约破坏性变更 = 新契约版本 + 新步骤版本（禁原地改）；回滚 = 指回旧版本。

## 十三、业务接入契约（框架对业务的保证面）

| 业务提供 | 框架承载 |
|---|---|
| 步骤实现（统一签名，只写操作段） | 注册表/五段执行/异常策略 |
| 流程定义 YAML | 编译六关/版本化/回滚 |
| 契约与异常策略配置 | contract 引擎/policy 引擎（含 abstain） |
| 同步读路径/状态机 | api 单元挂载点/事件入队通道 |
| 软信号契约 | 判定型步骤 `confidence` 断言（缺字段拒注册） |

接入清单（checklist）：步骤注册 □ → 契约映射与合同测试 □ → 流程图定义与六关校验 □ → 异常策略（含 abstain）□ → 资源档与队列 □ → 幂等键 □ → 优先级归属 □。
