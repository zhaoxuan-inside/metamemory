# MetaMemory 与 Mem0 对比分析

> 回答：**与最接近的参照系（Mem0，含 v3 现状）的异同是什么、每一处差异的性质与评估**。结论服务于架构界定（核心层 = 接收信息 + 查询信息两件事，见《产品设计》§十五 / ADR 14-17）与切片交付优先级。《设计原理》§四 为研究清单视图，本文为完整分析。

| 项目 | 内容 |
|---|---|
| 版本 | v0.2（逐级传导 v0.5/v0.6：切分与四态路由进协议对比 / 再巩固窗口强化 supersedes 语义差异 / 双指标基准锚扩展） |
| 日期 | 2026-09-24 |
| 层归属 | 【跨层】协议级对标：核心层（开源）与 Mem0 同位竞争；业务层产品不进对比 |

---

## 一、定位

| | Mem0 | MetaMemory 核心层 | 结论 |
|---|---|---|---|
| 本质 | 记忆 API 服务（`add()` 存 / `search()` 取，应用组装 prompt） | 收发协议：接收信息 + 查询信息 + 不可拆横切（裁决/审计/计量/置信溯源） | **核心层与 Mem0 是同位竞争**（协议级）；MetaMemory 的差异化在业务层（知晓网络），不在协议层 |
| 用户模型 | 开发者唯一主体，user_id/agent_id/run_id 是过滤标签 | 域主权主体，key 即查询者、裁决在服务端 | 协议级唯二的本质分叉之一（见 §三-②） |

## 二、趋同部分（均为本项目主动吸收，低风险）

1. **命题化提取、原子为资产单位**：双方收敛；
2. **"不删除"**：Mem0 v3 放弃 UPDATE/DELETE 变异，纯 ADD-only（v1/v2 两阶段 ADD/UPDATE/DELETE/NOOP 已废弃）；本项目灰色遗忘降权 + supersedes 关闭——且 supersedes 重写被**读后再巩固窗口**（72h，设计原理约束 11/R2）进一步约束：旧事实的关闭动作在读命中窗口内行使，超过窗口按新派生门禁；Mem0 的 decay 软重排无窗口语义，两者不构成等价互换；
3. **多信号检索融合**：Mem0 语义（唯一召回源）+ BM25/entity 两路 boost；本项目五路并行；
4. **重复前查重**：Mem0 先取 top-10 相关记忆做去重上下文；本项目第 0 层查重短路——同一思想两种实现；
5. **交付形态**：开源本地 + SaaS 双形态同构（Mem0 OSS 砍图记忆；本项目 lite 档砍 RLS 多租户——同类 OSS 边界策略）。

需注意的事实：Mem0 的 decay 是可选检索时软重排（0.3×–1.5×，ramp 后 rerank 默认关闭），“BM25 是 boost 不是召回扩展”意味着其召回面 = 语义单路。

## 三、残余差异（核心层探索后只剩四项）

> 架构重定义（ADR 14：核心层只做接收与查询）后，intent API、简报、L4 生成发布、计量闸门等不再计入协议对比——它们是业务层产品。核心层 API 面收缩为与 Mem0 同构的动词集：add / search / get+history / delete(update 经 manage)。

### ① add 的受理语义（任务式 vs 同步）

| | Mem0 | MetaMemory |
|---|---|---|
| 模型 | 同步：单遍 LLM 调用后立即返回提取结果 | 202 + task_id，管道（**单元切分 →** 提取/NLI 校验/锚定/**四态路由含 abstain 转复核**）异步；SSE/Webhook 进度 |
| 快通道 | 无（提取完才可检索） | 原文层同步直写，<100ms 可检索 |
| 质量责任 | 部分：`infer`/自定义 prompt 开放给调用方 | 服务端不可协商项（引文锚定 + NLI 闸门，调用方无 prompt 参数） |

**评估**：Mem0 的同步返回是开发者体验的核心；代价是提取质量取决于调用方 prompt、不可审计。本项目任务式的代价是“我记住了什么”不即时（快通道兜底预期），收益是忠实率成为服务属性。**方向正确；受理响应必须携带“原文已落袋 + 快通道已可检索”确认语义。**

### ② search 的裁决语义（指标签 vs 裁决者）

| | Mem0 | MetaMemory |
|---|---|---|
| 身份 | `filters={user_id}` 调用方自报（诚实依赖） | key 即查询者上下文；同一 search 返回三重搜索面（自己/他人/公共），结果集由视野铁律决定 |
| 召回 | 语义单路 + 两路 boost（BM25 不扩召回） | 五路全召回源 + RRF + rerank + 置信×强度；**检索意图三分 quality profile**（事实问答/时点定位/自传检索，设计原理 R5） |
| 返回 | 单一 score | score + 置信标注（"你明确说过" vs "我推测"）+ `{memory_id, span}` 溯源 |
| 特色 | threshold/rerank 参数 | **精确验证模式**（断言验证+引文证据）+ **grep 兼容 JSONL**；切分参数与召回可对账的**双指标基准锚**（v0.4 行动项-4） |

**评估**：这是协议级仅剩的另一本质分叉——“一个 search，搜得到什么是你的授权决定的”。Mem0 做不到（其 key 无被代表的查询者概念）。差异化清晰、可单句讲完，是核心层对 Mem0 的真实超越点。唤醒 P99 < 300ms 含 rerank 的预算偏乐观（Mem0 实测 rerank +200-400ms 且默认关），**降级链应包含 rerank 可降档**。

### ③ 管理语义（CRUD vs 写侧治理）

Mem0：update/delete 是行级 CRUD，改完生效，无级联。本项目：纠错触发血缘回溯下游重算、遗忘双轨（灰/硬）、升档走确认链。**评估**：血缘在数据模型里，治理无法下放业务层——这是核心层比 Mem0 重的不可削减项；但 manage 一个动词承载四类语义过重，**拆 correct / visibility / authz / forget 四个显式子动词**以便审计与计量按意图归因。

### ④ context（可选增值动词）

Mem0 无（官方定位“应用自己组装”）；本项目 context = token 预算组装 + 多粒度 + 溯源。**评估**：自有场景（分身/简报）必需；对第三方是可选高级件——**add/search 必须独立闭环**，context 永远可选，防止协议面回到概念过载。

### 协议以外的显著点

- **鉴权**：Mem0 API Key = 身份；本项目 key scope 直接映射视野档位——ecurity 与 search 的裁决语义是同一件事的两面；
- **MCP**：双方均有官方 MCP 接入；工具语义差异（Mem0 的 Agent 可直接 add/delete；本项目 intent.* 永远产候选）是信任定位在协议层的落点；
- **计费**：Mem0 订阅制；本项目核心层配额封顶 + 按量（横切，不影响协议面）。

## 四、评估结论

1. **核心层协议对比后，与 Mem0 的差异只有三项**：任务式受理（质量闸门不可绕）、search 服务端裁决（唯一本质分叉）、写侧治理级联（血缘不可下放）。三项全部可在一页开发者文档里讲清——API 极简风险已随核心层界定消解；
2. **Mem0 v3 的教训采纳**：图记忆成本 > 多数客户收益（OSS 已砍图）——本项目图谱 MVP 先做检索 boost 用途的轻图（CTE 两跳），建边治理全量随 S2 治理层到位；
3. **业务层是差异化所在且不在协议对比中**：意图（供给侧进入公开层使“搜他人”有内容）、简报（search 的定时消费）、L4 发布（公共层搜索面的供给）、撮合（search 的消费方）。Mem0 没有这一层，这是竞争从产品级退到协议级后 MetaMemory 的全部商业赌注；
4. **行动项**：S1 起用 LongMemEval / LoCoMo 直接对账 Mem0 公开分数（协议质量的外部锚，也是《设计原理》§七的外部校验点）；黄金集 v0 构建方案见《产品的技术选型》§2.2（v0.2 起含 abstain 四态标注与"边界切错"失败类目）；**外部锚须补中文对话集**（LongMemEval/LoCoMo 目前无中文对话——设计原理 v0.6 §九已标注），另选定表示层探测 probe 集作为内部表示质量的中间锚（仅参数调优不充当对账结论）。
