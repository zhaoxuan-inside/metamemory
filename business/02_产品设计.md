## 一、产品概述

### 1.1 一句话定位

**"你的分身替你记住了整个世界，然后只把'你此刻该知道的'给你。"**

不研发基础大模型，不做前端 ChatBot——做模型无关、跨平台中立的记忆中间层：所有 AI Agent 的"海马体"与"外脑"，以及在此之上生长的意图撮合网络。

### 1.2 产品本质：从记忆引擎到认知引擎

记忆只是原料，产品的价值单位是"**用户能知道什么**"：

```
你该知道的 = 你的过去（记忆）× 相关的他人（授权）× 相关的世界（信息流）
```

### 1.3 系统总览

整个系统 = **2 层（核心层 + 业务层）、1 个统一域模型、4 组横切机制**：

```
业务层（增值产品，全部只经 add/search 消费核心层）
  │  分身空间（单成员域皮）│ 记忆中枢（多成员域皮）│ 开发者面
  │  意图面板与确认链 UI │ 认知简报 │ L4 抽象生成与发布 │ 撮合/情报/信誉/权益（扩展业务）
  │
  ├─ 消费方式：业务层写入 = 记忆事件（add）；业务层读取 = 裁决过的 search/context
  │            禁止旁路：import-linter 白名单技术强制，非纪律
  │
核心层（收发协议，对标 Mem0 的位置）
  │  接收信息：add（受理落袋→归一→门禁→查重→提取→锚定→校验→打分→组织）+ 纠错/遗忘（写侧治理）
  │  查询信息：search（五路+融合）+ context（组装表达）+ 精确验证模式；网络=同一 search 的对外延伸
  │
统一域模型：域 / 成员（角色=属性）/ Agent 接入
横切：视野裁决 │ 溯源链 │ 置信度门槛 │ 审计与计量
框架层（驱动与基建，开源）：任务编排 │ 处理容器 │ 数据契约 │ Store 槽位 │ 防腐层
```

关键判断：
1. **核心层只做两件事——接收信息与查询信息**（架构裁定 ADR 14）；纠错/遗忘是接收的逆操作（写侧治理），置信/溯源是查询的出口语义；视野裁决/审计/计量是让两件事可信可卖的不可拆横切；
2. **不存在"个人版系统"与"企业版系统"两套实现**（个人域 = 单成员域），三张皮是同一域能力的投影；
3. **网络不需要独立的社交系统与网络 API**——网络即搜索：搜自己域内、搜他人（授权桥接/组织协作/定向可见/公开层检索）、搜公共信息（代理采集回灌 add 后经 search获知），是同一个 search 经查询者裁决返回的不同结果集（ADR 15）；
4. **遗忘的目标是给整个网络减负**——衰减/灰色遗忘/压缩是检索空间的治理，把全网信息聚焦到最近被关注的事情上；治理指标**双轨分置**：存储完备率（写侧）与检索召回率（读侧，基准对账），不得用一个伪装另一个（设计原理裁定 R3）；
5. **意图/简报/L4 生成发布/撮合等增值产品全部属业务层**，消费核心层数据，不旁不路；
6. **三层两仓的开源边界**：框架层（驱动与基建）+ 核心层（收发协议）开源，业务层（增值产品与网络资产）闭源——"关于自己的知晓"全部在开源两层内完整可行，网络效应产物云端独占（ADR 21；《运营推广策略》§3.2）。

## 二、统一主体模型：域

### 2.1 一种实体 + 属性差异

系统中只有"域"一种容器实体——个人域、团队域、公司域、中介域在实现上无类型分支（"个人域"只是成员数 = 1 的事实称呼）；单成员域 → 公司域的成长**零迁移**。

### 2.2 角色即属性

角色是成员身上的数据标签：参与**信息的评判**（谁能看组织 L1、谁可审批），不影响系统逻辑。新增角色 = 属性值 + 一条规则数据，零代码路径。常见"特殊角色"的统一表述：中介域 = 普通域（其供给恰好是撮合服务）；认证供给方 = 无此角色（信任来自履约记录与信誉）；B 端/C 端 = 称呼习惯非系统实体。

### 2.3 三条主权规则

| 规则 | 机制 |
|---|---|
| 子域主权 | 个人域记忆（L1/L2）组织域进不来——**跨租户读取被 RLS 直接拦下，不靠业务裁决**；公司聚合层只能看到子域主动上报的 L4 统计 |
| 域内产生归域所有 | 记忆携带归属域；个人成员拥有**引用副本权**（对话史可带走）；离职交接 = 副本转正 + 双侧确认 |
| 跨域授权即桥接 | 个人域 ↔ 公司域的数据流动与对外授权完全同构，无"组织内免检通道" |

## 三、视野模型：知晓边界（L1-L5）

### 3.1 六档光谱

| 档位 | 个人记忆 | 组织记忆 |
|---|---|---|
| L1 私有 | 仅本人；授权 Agent 会话可用但不落第三方 | 组织内指定角色 |
| L2 授权 | 授权特定 Agent 持续读写 | 组织内全员可见 |
| L3 域内 | 同组织成员经授权可见 | 组织内全员可见（知识沉淀） |
| L3·D 定向 | 对指定外部对象定向公开（双向各一条定向授权） | 对指定外部对象定向公开 |
| L4 抽象 | 域对"我能提供的信息"的发布投影：服务端生成的脱敏画像（生成/发布分离），发布后任何 Agent 可检索 | 抽象后的组织信息全公开 |
| L5 公开 | 主动公开的偏好/意图 | 本来就公开的信息 |

> 六档口径（反向检查 N1 裁定）：**六档 = 五级（L1–L5）+ 定向变体**——L3·D 是 L3 域内档对域外对象的定向变体，共用 L3 级代号、独立成档计数；对外统一表述"六档视野（L1–L5 + 定向）"。

### 3.2 跨档铁律（三不越权 + 发布投影）

1. **升档需确认，降档即生效**；
2. **派生不越权（三不越权）**：① 信息量不越权；② 血缘单向（外部不可经血缘逆向取源——公开的是投影不是源）；③ 生命周期不越权（源失效 → 派生级联）；
3. **L4 = 发布投影**：服务端自动生成（草稿态域内可见）→ 按域级规则一次性发布授权（替代逐条确认）→ 事后审阅/修改/否决。四道防线：发布主权 + 抽象度 + 事后治理 + 低置信输入隔离；
4. **检索时按查询者身份过滤**；
5. **撮合方向性原则**：偏好出域只走 L4 抽象通道，外部信息进来在域内匹配。

### 3.3 授权三元组

```
授权 = 视野档位 × 使用目的 × 时效
```

- 粒度：按条目 / 主题域 / 时间窗；到期自动收回；随时撤回（撤回后停止未来检索——已进入对方会话的上下文无法追回，界面明示）；
- 每次裁决放行写审计流（谁、何时、以什么授权、读了哪条）。

## 四、记忆引擎（核心层：接收与查询，九大能力域）

> 归属界定：本节全部能力域属**核心层**——四与五是收发协议本体（ADR 14）；六（意图）/七（网络即搜索）/九（简报）中的核心层部分仅为字段与裁决规则，产品面归业务层（ADR 14-16）。

**总原理：记忆是一条管道，不是一个仓库**——获取（输入归一）→ 理解（结构化）→ 组织（建网）→ 巩固遗忘（强度治理）→ 唤起（五路检索）→ 表达（预算内组装）；推理与信任横贯，演化改写参数。每个能力的**具体信号、算子与容器**见《核心层功能实现》（核心件）与《业务层功能实现》（业务件）。

### 4.1 获取

一切输入归一为统一的记忆事件流：对话流捕获（**快通道**：同步落袋原文层，零 LLM）、多源导入（文档五段式解析 / 结构化事件化 / 轻导入档）、主动情报采集（代理阅读）、多模态；入口幂等（同事务入队）。业务层行为事件（握手/成交/履约/评价）也以记忆事件进入，归属产生它的域。

归一之后、理解之前是**单元切分**——写侧第一决策（设计原理约束 13）：从连续流中发现记忆单元（对话轮/文档段/事件）依据是统计信号（邻接转移概率可归因，语言学实证：婴儿凭 2 分钟音节流完成切词——切词无显式边界时统计即可，Saffran 1996）。切分粒度/边界是**演化参数**不是出厂常数；证据 span 原样保底，切分损失可逆。快通道"零 LLM"承诺不变（切分不依赖强模型）。

### 4.2 理解（壁垒核心）

把非结构化内容转成语义原子：五维价值信号选取 → 强模型命题化 → 引文锚定 → NLI 忠实校验 → 价值打分三态路由（提取/折叠/留原文）。产出原子 = 内容 + 实体引用 + 时间 + 类型 + provenance（S1-S4 + 置信分）+ 视野初判。**质量受六指标 CI 门禁约束**（忠实率降级阻断发布）。详见《核心层功能实现》§三。

三条硬约束（源自设计原理 v0.6 约束 13/14/15 与 §2.6）：
1. **前置层软信号**：第 0 层分类器级联（安全/PII/分类路由/查重短路）输出携带置信、可被下游更强裁决推翻并回写；硬裁决只有两处——安全/PII 门（fail-closed，只能收紧）与确认链（约束 14；语言学背书：低层决定常被高层回溯修正，Tenney 2019）；
2. **三态路由升级四态**：提取 / 抽象折叠 / 留原文 / **弃权待复核（abstain）**——判不了的显式挂起人裁，禁止默认落置（约束 15，Turing 不可判定上界）；
3. **流畅 ≠ 合式**：置信模型不采"生成流畅度"作质量信号——结构合法性独立于语义可接受性（Chomsky 1957）。

### 4.3 组织

四类分层（语义/情景/程序/意图）+ **关联建网**（八类边、三个时机、实体统一三级级联、谓词归一、双时态落库）+ 记忆抽象（L4 管道）。详见《核心层功能实现》§五。

**派生分级**（设计原理裁定 R9）：抽象生成（L4/模式）不与具体结论同门槛——从具体条目的复用中渐进涌现（item-based 渐进抽象，Tomasello 2000）；先固化稳定复用的具体结论，schema 级抽象须挂**严格版巩固收益门**且显式引用其复用证据。

### 4.4 巩固与遗忘

巩固（重复/高频检索/情感 → 转长期）；衰减（淡化不删除）；主动遗忘（遗忘权硬删、意图过期、合规删除）；压缩（细节折叠为模式，可溯源展开）。遗忘双轨分开承诺：灰色遗忘（降权可恢复）与硬遗忘（不可恢复）。

两处升级（设计原理 v0.6/R1-R2）：
- **巩固是选择性的**：向结构化层/长期层的固化必过巩固收益门（复用频次 × 跨情境度 × holdout 增益），无泛化收益的自动派生禁止静默入库（约束 10）；
- **读取即再巩固窗口**：检索命中即重置强度 Δt 并开启改写窗口（默认 72h）；supersedes 重写与衰减重置只在窗口内行使，窗口外写入走派生门禁（约束 11）。

### 4.5 唤起

单一检索路径必然漏——**五路并行**（语义/全文/关联图谱/时间线/情境触发）+ 融合排序（RRF → reranker → 置信 × 强度）+ 联想召回（图谱多跳）+ 每条结果带置信度标注（"你明确说过" vs "我推测的"，不掩盖）。公开层检索（L4/L5）是唤起在全网范围的变体。

**检索意图三分**（设计原理 2.2/裁定 R5）：读取按意图分三层质量门——事实问答 / 时点定位 / 自传检索，三类走不同召回与校验深度（哲学 episodicity 判据映射）——读取路不新增 API，是 search 的质量分层参数。

### 4.6 表达

Context 组装 = Token 预算内择优：候选按融合分 × 置信 × 强度排序装入，附加溯源引用（点开直达出处），按接收方选择多粒度（摘要/条目/原文）。同一组装器服务分身对话 / Agent 取数 / 简报。

### 4.7 推理分层（内置 / 可选 / 外置）

| 层 | 内容 | 定位 |
|---|---|---|
| 内置 | 消歧与合并、冲突消解、时效推理、抽象生成、置信度计算 | 维护记忆所必需，客户无感 |
| 平台可选 | 归纳 API（记忆集→模式结论）、预测 API（行为→需求预测） | 独立计费 |
| 外置 | 业务推理、对话策略、个性化话术 | 不抢客户的活 |

### 4.8 信任（授权）

授权粒度（条目/主题域/时间窗）、时效授权、随时撤回、代理授权边界、授权审计——全部是授权记录与裁决器的属性，不是独立系统。

### 4.9 演化（反馈与优化）

**反馈是记忆系统的代谢。** 三级信号（显式：纠错/有用/无关/举报；隐式：唤起后消费/对话否定/长期零唤起/简报打开；系统内：忠实率/纠错率/唤起兑现率）→ 每个信号有唯一归属的改写对象 → 三级闭环（L1 参数微调自动生效 / L2 策略变更批量触发 / L3 管道变更过回归门禁）。

**参数清单随 v0.6 扩展**（"反馈只改参数"同规）：单元切分粒度与边界参数（约束 13）、前置分类阈值（安全/PII 门之外，约束 14）、派生分级抽象门阈值（R9）——均可演化但不触及决策骨架；新增中间质量探针：表示层结构探测（probe 集合，Hewitt/Tenney 背书）作为召回对账的补充信号进演化闭环，仅用于参数调优，不充当自动裁决。

**四条禁区**：① 按域隔离（个性化不跨域共享）；② 边界不是参数（视野/授权/免费边界不可被优化触碰）；③ 伦理红线不可优化突破（简报"温和观察"不允许被推向心理评判）；④ 演化可解释（分身可查看"因我的反馈调整了什么"）。

## 五、记忆正确性与冲突治理

1. **来源分级与置信度**：S1 用户明示 / S2 对话推断 / S3 导入 / S4 二次推理；`置信 = 来源级别 × 抽取分 × 时间衰减`；纠错是最高优先级信号；
2. **冲突三分法**：时间演进型（确定性规则关闭旧原子，自动）/ 粒度差异型（并存，按情境取用）/ 真矛盾型（冲突卡片挂起，裁决前不参与 L4 与撮合）；挂起裁决结果回流为 S1；**自动链每级显式弃权（abstain）即挂人裁，禁止默认值兜底**（约束 15，Turing 上界）——"判不了"是合法结论不是失败路径；
3. **低置信隔离**：可检索带显著标注；不参与 L4 抽象、撮合信号、简报"该想起的"；
4. **记忆体检**：随周刊推送"待确认清单"（低置信/真矛盾/长期未验证），批量确认/纠错/遗忘；
5. **错误不扩散**：纠正沿血缘回溯下游（派生记忆/L4/画像字段）同步重算。

## 六、意图系统（业务层消费核心层的产品）

> 归属界定（ADR 14）：意图作为**记忆类型**（时效、可交易、需确认的记忆）留在核心数据模型与接收管道（intent_details 表、状态机位）；本节的**面板/确认链交互/时效运营是业务层产品**——经 add（观察产候选）与视野变更（visibility 决定可发现性）消费核心层，不走独立写 API。核心层对意图只有字段与状态机约束，零产品语义。

### 6.1 定义与双入口

意图 = 唯一"有时效、可交易、需确认"的记忆——"未来的事"。**双入口**：用户主动声明（直接生效，可见性自选）；Agent 观察捕捉（**只能产候选**，默认仅自己可见，确认卡片后才可能被发现）——Agent 永远不能替用户"有意图"。组织同构：员工观察 → 部门负责人确认 → Admin 批准（审批人是角色规则数据）。**全网意图确认链只有一条。**

### 6.2 意图面板

三个页签（生效中/已过期/已完成）；**三旋钮**：有效期（一周/一月/直到关闭）、可见性滑杆（仅自己 → 脱敏画像可检索 → 完全公开，每一档是一次视野变更）、期望回应（要方案/直接聊/只收信息不打扰）；机会收件箱与完成记录（业务层承载，核心层只提供状态与可见性变更入口）。

### 6.3 时效推理

有效期到期 → 自动转"已过期" → 归档退出发现索引（血缘下游级联撤下）→ 进遗忘管道。意图记忆永远免费存在；**配额口径（G3 裁定，全网逐字统一）**：免费档 = **3 个"生效中意图进入发现网络的位数"**，个人 Pro 不限——配额限发现服务位数，**不限意图本体**（保存/唤起/纠错永远免费）；数字为提案值，随计费评审回填。

## 七、查询即网络（核心层 search 的对外延伸）

网络不是子系统，是核心层 search 的对外延伸——一个 search 端点，三重搜索面由查询者上下文与视野裁决区分：

| 搜索面 | 内容 | 机制 |
|---|---|---|
| 搜自己域内 | 我的信息全量 | 查询者 = 域 Admin/本人上下文，L1-L5 全可达 |
| 搜他人 | 他人愿意让你知道的（L2/L3/L4/L5） | 授权桥接（任意两域 = 一条授权三元组）、组织协作（成员关系 + 角色规则）、定向可见（绑定目标域的授权记录）、公开层检索——**检索是基础设施，解锁是授权动作** |
| 搜公共信息 | 公开信息与外部情报 | 公开发布（L5 升档 / L4 抽象，发布动作属业务层）、公开层检索、代理阅读（采集回灌 add，回来的是"你会想知道的"，经 search 获知） |

`filters` 式调用方自报身份不可接受（对照 Mem0 模型）：**key 即查询者，裁决在服务端**——同一端点、同一调用语义，结果集由视野铁律决定。

**发布管道**：域记忆 → 生成草稿 → 分面标注（业务语义归业务层）→ 选公开层级 → 入公开索引（携带来源记忆引用）→ 域记忆更新自动提议更新。

## 八、产品功能面：三张皮，一个引擎

| 皮 | 模块 |
|---|---|
| **分身空间**（单成员域） | 记忆管理（时间线/图谱/全文检索/纠错/遗忘双轨）、授权中心（Agent 列表/三元组管理/审计流）、意图面板、分身对话（官方 Agent 接本域全部记忆——新用户第一体验）、权益账户 |
| **记忆中枢**（多成员域） | 知识接入、组织视野管理（L1-L5 管理台/L4 审阅）、内部赋能（员工/客服 Agent 按角色过滤）、公开层检索台、公开发布台、计费审计 |
| **开发者面** | Memory API（add/search/context/manage + 精确验证模式 + grep 兼容输出）、Intent API（上报永远产候选）、授权 SDK（确认卡片内嵌对话流）、MCP Server（memory.* / intent.*） |

## 九、核心模块：认知简报（业务层产品）

> 归属界定：简报 = 业务层对核心层 search 的定时消费（栏目选取器族即参数化 search）+ 渲染送达。核心层零简报语义。

**简报不是推送，是分身每天来见你**——五个知晓场景里唯一主动发生的地方。两份刊物：晨报（30 秒"该想起的"，3-5 条每条一句话）、周刊（自我认知的镜子：画像更新/变化轨迹/月度唤起/体检清单）。

```
晨报 · 9月21日          你的分身
【该想起的】三年前的今天，你和林老师聊到想一起做播客——还没开始
            你上周答应客户发的方案，明天是第三天
【你自己没意识到的】这个月你提到"记忆"17 次，上个月只有 3 次
【与你相关】2 条新情报与你"Agent 记忆项目"的意图相关
【你的分身替你读了】今天替你读了 34 条行业动态，3 条你会想知道
```

- 五栏目精确对应五个知晓场景；**"你自己没意识到的"是杀手栏目**——伦理红线：只做温和观察，不做心理评判；
- 冷启动：Day 0 初识对话（10 分钟结构化对话产首批 S1 记忆）→ Day 1 第一份晨报的仪式感（"第一天，我记住了你的 7 件事"）→ 每日必达，**宁可短不可断**（心跳机制）；
- 信任机制内嵌：每条可溯源（点开直达出处）、可纠错（长按当场修正）、可反馈（1 秒训练分身）。

## 十、业务层界定（构建在核心层两动词之上的增值产品）

> 原"扩展层"随架构重定义（ADR 14）正名为业务层。业务层**不拥有任何旁路**：写入 = 记忆事件（add），读取 = 裁决过的 search/context；耦合点是核心层的两个动词族，不是数据表。

**业务层产品清单**：意图面板（中心化意图管理）、需求情报台（五分面模型/三层活词表/三种订阅形态/供给反推流）、需求景气指数、域信誉档案（信誉 = 行为记忆的公开投影）、权益分成闭环、L4 抽象生成与发布管道、组织管理台、分身对话与记忆中枢两张产品皮。**排期（反向检查 C12/C22 标注）**：意图面板/简报/L4 发布/intent.* = S3 起业务层首批；需求情报台/景气指数/信誉/权益分成 = **业务层二期立项（S3 后）**。拆分件见《业务层产品设计》《业务层功能实现》（业务层_闭源/）。其实现方案待立项另编，只界定两件事：

1. **消费方式**：业务层向核心层只发两类调用——记忆事件（add：观察/交互/履约/评价事件化）、裁决过的查询（search：意图发现/画像检索/情报组装）；L4 生成产物经 add 事件回流核心层（P 类标记），发布动作只做视野变更；
2. **遵守的约束（技术强制）**：业务层代码禁止直连 Store 槽位、读路径内部与 VisionArbiter 之外任何读取面——import-linter 白名单（业务层 steps → 核心层 add/search 入口）CI 阻断；偏好明细与原始记忆不出域；业务词表由业务层定义不固化进核心。

撮合用户体验（供理解，本质上也是 search 的消费方）：猎头 search 到"某大厂 5 年后端，在看机会"（L4）→ 发起请求（add 事件）→ 用户机会收件箱（业务层视图）→ 相互解锁（视野变更动作）→ 标记成交/不合适（add 履约事件）。**撮合无撮合引擎专属 API——检索即撮合的入口。**

## 十一、隐私与信任

1. 视野模型即隐私架构（唯一机制，无特殊通道）；2. 撮合全程"门禁人"（用户永远握着门禁）；3. 偏好不出域；4. 遗忘双轨分开承诺；5. 代理授权边界（Agent 只能提议意图）；6. 撤回边界明示；7. 端侧演进（远期：端侧小模型提取，云端只存图谱节点）；8. 信任基线（接入 Agent 视为可信代理，Agent 侧行为治理列为远期）；9. 隐私事故防线（§11.1）；10. 组织域合规边界（§11.2）；11. 伦理红线扩展（§11.3）。

### 11.1 隐私事故防线（L4/撤回盲区的纵深防御）

"已进入对方会话的上下文无法追回"与"L4 事后否决"是两个内生的泄露窗口。防线不是单点：

| 防线 | 机制 | 归属 |
|---|---|---|
| ① 生成侧降险 | L4 抽象生成带"泄露评分"（NLI 泄露复核已定）——评分超阈的草稿**默认不发布**，域级发布规则只能放行低险草稿，不能豁免高险 | 业务（l4.abstract 管道加闸） |
| ② 发布侧缓冲 | 草稿态 → 发布后 72h 内为"可无痕撤回窗口"（公开索引可见但下游检索结果带失效标记，撤回时下游缓存同步失效）——把"事后否决"从事后补救变成有时间窗的可逆动作 | 业务（published_items 增撤回级联） |
| ③ 消费侧约束 | 对外输出的上下文组装带水印标记（记忆 id + 视野档位嵌入文本指纹），泄露事件可回溯泄露源 | 业务（express 组装器）+ 框架（审计流） |
| ④ 事故响应 | 泄露响应预案为本期必做（见 §十四 修订）：泄露定级 → 受害域通知 → 溯源链回放 → 下游失效广播；执法调取流程公开明示（透明度报告承诺） | 框架（审计回放）+ 业务（通知/失效） |

### 11.2 组织域合规边界（员工记忆监控）

组织域对成员记忆的可见性受法律硬约束（PIPL / 劳动法 / GDPR），机制上落为规则数据而非新系统：

1. **知情与同意前置**：成员加入组织域时，其 L1/L2 哪些档位对哪些角色可见，必须逐项明示确认（同意记录入审计流）——默认不可见，可见是明示结果（与公理"升档需确认"同构）；
2. **目的限定数据化**：授权三元组的"使用目的"在组织域场景升格为合规要求——成员记忆仅可用于入域声明的目的（协作/交付），不得用于绩效评价/监控（目的字段进入裁决器精裁，违反即拦截并审计告警）；
3. **成员否决权**：成员对"组织角色可见自己的哪条 L1/L2"有单条否决权（降档即生效原则在组织域的直接适用）；
4. **法域差异**：跨国组织的合规差异（数据出境、员工同意效力）列为开放问题，但"默认不可见 + 目的限定 + 单条否决"三原则在全部法域成立。

### 11.3 伦理红线扩展（原第 9 节四条禁区之外）

| 场景 | 红线规则 |
|---|---|
| 健康与心理 | 健康状态、心理状态推断（抑郁/焦虑倾向类）永不进入简报"你自己没意识到的"栏目与画像字段；即使证据充分也只提示"分身注意到一些变化，建议你回顾相关记忆"，不输出结论 |
| 亲密关系推断 | 关系性质推断（暧昧/矛盾/疏远类）不出现在任何主动输出（简报/画像/L4），仅限用户显式检索时带推测标注返回 |
| 法律取证请求 | 记忆系统不提供"取证模式"；执法调取走 §11.1-④ 流程，域内记忆不因执法请求改变视野 |
| 分身表态责任 | 分身对外输出（Agent 取数/公开层）永远以"来自某域的整理"署名，不模拟第一人称表态；用户可为分身输出做"本域已确认"背书（背书是用户动作，不是默认） |
| 数字遗产/未成年人 | 列开放问题，但基线先立：未成年人域默认仅监护人有限视野（L5 不开放）；数字遗产在明确立法/判例前默认按硬遗忘处理（不继承） |

## 十四、范围界定与开放问题

**本期明确不做**：跨域删除传播、女巫攻击防护、情报防再识别与防绕单（随业务层立项必做，不随撮合上线裸奔）、家庭域（宣传页已标"即将上线"，反向检查 G2）、推广营销（见《运营推广策略》）。

**本期必做（原"不做"清单中提升）**：
1. **安全架构基线**（原"安全架构细节不做"修订）：加密（敏感字段 AES-GCM 已定）、密钥轮转、泄露响应预案（§11.1-④）、执法调取流程明示——信任产品的安全篇不可缺席；
2. **导入记忆中的第三方权利**（原明确不做，修订）：对话对方知情提示（"分身在记这段对话"入口明示 + 可请求删除自己相关的原子，走本域纠错通道）；完全的第三方权利义务体系仍不做；
3. **跨域删除传播的最小形态**：已发布条目（L4/L5）的硬删/撤回对公开索引下游发失效通知（不承诺全网清除，承诺"源头失效 + 已知下游通知"）——这是 §11.1-② 的机制复用；
4. **Agent 侧行为治理·基线版**（原"远期"，修订）：MCP/SDK 上线前必须有——API Key 级速率与配额（已有计量闸门承载）、意图候选提交频控、授权请求频控与批量拒绝、公开层检索限流。完整行为信誉体系仍属业务层；
