## 一、业务容器总则

- 全部容器以 L1 配置注册进框架（YAML 形态见《框架设计》§3.7）；
- **只经核心层两动词族消费**：写入 = add（记忆事件化），读取 = 裁决过的 search/context（import-linter 白名单，ADR 16）；
- 业务层行为（握手/成交/履约/评价）以记忆事件回流核心层——**记忆化而非旁路化**。

## 二、业务容器注册表

| 容器 | 提取信号 | 压缩效应 | 关系效应 |
|---|---|---|---|
| l4.abstract / publish | 置信门槛 + **schema 级抽象挂严格版巩固收益门（R9，显式引用复用证据）**；生成草稿在核心层，发布动作为视野变更 | 抽象即压缩 | 血缘指回；**撤回级联**：发布 ≤72h 无痕撤回窗（降险缓冲）、硬删/撤回 → 公开索引失效 + 已知下游通知（最小跨域删除，《02_产品设计》§十四-3） |
| brief.select / render / deliver | 栏目信号（参数化 search） | 表达层压缩（3-5 条） | — |
| intent.panel / card / inbox | 确认链事件（SSE 卡片经核心层推送通道） | — | 意图状态机位变更（核心层承载） |
| feedback.ingest | 三级信号（显式/隐式/系统内） | — | 信号回灌 add 事件 → evolution_params 热生效（演化闭环） |
| match.rank / intel.feed / reputation.view / billing | 公开层检索结果 + 目的闸放行记录 + 履约事件聚合 | — | 网络资产（云端独占，开源版无） |

**简报伦理落点**：brief.select 的"你自己没意识到的"栏目候选过滤为**硬编码常量**（健康/心理推断类、亲密关系推断类原子结构性排除，禁区②具象化）——见《业务层产品设计》§三。

## 三、业务流程图（数据化流程定义，CI 校验后装载）

| 流程 | 图形态 | 触发 |
|---|---|---|
| brief | 栏目族 **fork** 并行 → 置信过滤 → 渲染 → 送达 | 每用户时区 cron |
| publish.l4 | 草稿生成（核心层）→ 分面标注 → 域级规则审阅 → 发布（视野变更）→ 72h 撤回窗监控 → 撤回级联 | 用户/域级规则触发 |
| match.flow | 检索（search 公开面 + 目的闸）→ 请求 add → 收件箱 → 解锁（视野变更双向）→ 履约 add → 分成/抵扣 | 业务层事件 |
| feedback | 信号采集 → 归因 → L1 参数微调（自动）/ L2 策略批量 / L3 管道过门禁 | 持续 |

## 四、工程形态：闭源仓库结构（metamemory-x）

```
metamemory-x/（闭源仓：业务层）
├── flows/x/        # brief / publish.l4 / match.flow / feedback（业务层流程）
├── contracts/      # 业务契约与异常策略（继承框架契约引擎）
├── x/              # 【业务层】增值产品（只经 core 的 add/search 入口）
│   ├── briefing/   #   简报（选中/润色/送达）
│   ├── network/    #   publish / 撮合 / 情报 / 信誉 / 权益
│   ├── intent_ui/  #   意图面板 / 确认卡片 / 机会收件箱
│   └── feedback/   #   三级信号采集
├── api/            # 业务端点挂载（SaaS 面）
├── data/           # 业务表仓储 + 迁移分支
└── bootstrap.py    # 组合根：import 核心层组合根 → 注册业务容器 → 装载业务流程 → serve
```

import 单向：`metamemory-x → metamemory(core) → metamemory-framework`；开源用户只装前两层即可完整行使域主权（lite 档全闭环），业务层是云端增值。

## 五、排期与边界

- 意图面板/简报/L4 发布/intent.*：S3 起（业务层首批）；
- 撮合运营/情报台/景气指数/信誉/权益：**业务层二期立项（S3 后）**；
- 开源版无业务层：开源 README 明示"网络效应产物云端独占"（《运营推广策略》§九 纪律条款）。
