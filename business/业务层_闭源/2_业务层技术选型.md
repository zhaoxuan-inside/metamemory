## 一、选型原则（业务层专属补充）

1. **只经核心层两动词族消费**（add/search，import-linter 白名单，ADR 16）——业务层禁止直连 Store 槽位与读路径内部；
2. **业务词表业务层定义**，不固化进核心；
3. **网络资产云端独占**：撮合匹配/握手清算/信誉聚合/景气指数只在云端业务层实现（开源版无此能力，护城河所在，《运营推广策略》§3.2）；
4. 复用核心层的部署档位与可观测栈（OTel/Prometheus/Langfuse），不另建运维体系。

## 二、逐产品技术实现（自《技术选型》拆入）

### 2.1 认知简报

定时调度器（cron 表 + leader 选举）按用户时区 sweep；栏目选取器族（每栏目一个参数化检索）；嵌入式小模型一句话润色（模板防幻觉）+ Jinja2；渠道适配器（App Push/邮件/IM webhook）；心跳保底；反馈回流。

### 2.2 产品皮（三张皮的前端实现）

Vite + React 18 + TS + Ant Design + TanStack Query + Zustand；图谱 AntV G6；时间线 vis-timeline；分身对话 SSE 流式 + 溯源侧栏；移动端后期 Flutter 复用 API。

### 2.3 意图面板与确认链 UI

意图状态机的**核心字段与状态机位**在核心层（《核心层技术选型》§4.7）；业务层承载：三旋钮 UI（有效期/可见性滑杆/期望回应）、确认卡片 Web Component（内嵌对话流，SDK 分发）、机会收件箱视图、时效运营（到期提醒/归档视图）。SSE 卡片经核心层推送通道（三层通知）下发。

### 2.4 撮合网络与情报台（云端独占）

- 撮合匹配：公开层检索（经核心层 search 公开面 + 目的闸，约束 16）+ 业务层排序策略；**无撮合专属 API——检索即撮合入口**；
- 需求情报台：五分面模型（品类/画像/时效/动机/阶段）+ 三层活词表（词表社区治理见《运营推广策略》§六）；供给反推流（新需求 → 匹配供给域 → add 事件触达）；
- 需求景气指数：全网需求池聚合（业务层 OLAP 读模型，从 metering/记忆事件聚合，不经核心层）；
- 信誉档案：行为记忆的公开投影（核心层存行为事件，业务层聚合公开视图，双向对称可解释）；
- 权益分成闭环：成交 → 平台抽佣 → 分成/抵扣（billing_accounts）。

## 三、业务层技术决策

| # | 决策 | 理由 |
|---|---|---|
| X1 | 业务层独立闭源仓库（metamemory-x），import 单向：x → core（add/search 门面）→ framework | 三层开源边界的技术强制；网络资产保护（《运营推广策略》§3.2/§九） |
| X2 | 计费口径与配额：**生效中意图进入发现网络的位数免费 3 个（意图本体不限量保存）**，Pro 不限；发现/握手/情报按量与订阅 | 与《运营推广策略》§1.3 逐字一致；配额限发现服务不限意图本身（②公理 7 与《产品设计》§6.3） |
| X3 | L4 发布节奏：生成草稿（核心层）→ 域级发布规则 → 72h 无痕撤回窗 → 公开索引；**"自动进入公开层"的对外表述一律为"自动生成草稿、经确认发布"** | 发布主权与事后审阅是产品承诺（ADR 9）；营销文案不得越过此节奏（反向检查 C24） |
| X4 | 撮合/情报/景气指数 = 业务层二期立项（S3 后），不随核心层切片交付 | 《产品设计》§十 排期标注（反向检查 C12/C22） |

## 四、与核心层/框架层的边界对照

| 关注点 | 核心层（开源） | 业务层（闭源） |
|---|---|---|
| L4 抽象 | 生成管道（置信过滤/摘要/脱敏/NLI 复核 → 草稿） | 发布动作/域级规则 UI/撤回级联运营 |
| 意图 | 字段/状态机位/时效推理/确认链规则 | 面板/卡片/收件箱/运营 |
| 检索 | search 五路融合 + 视野裁决 + **目的闸（约束 16）** | 撮合排序/情报流/订阅分档 |
| 计量 | metering_events + 闸门原语 | 计费策略/账单/分成/抵扣 |
| 通知 | 三层通知通道 | 简报渲染/推送文案/渠道运营 |
