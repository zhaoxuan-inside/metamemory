## 一、归属界定（ADR 14 的业务侧展开）

业务层**不拥有任何旁路**：写入 = 记忆事件（add），读取 = 裁决过的 search/context；耦合点是核心层的两个动词族，不是数据表。核心层对业务产品**零产品语义**（意图只有字段与状态机约束、简报只是定时 search 消费）。

**产品清单与排期**：

| 产品 | 交付切片 | 说明 |
|---|---|---|
| 意图面板 / 确认链 UI / 机会收件箱 | S3 起（业务层首批） | 状态机位与确认链规则在核心层 |
| 认知简报（晨报/周刊） | S3 起 | 栏目选取器族 = 参数化 search |
| L4 抽象生成与发布管道 | S3 起 | 生成在核心层（域主权能力，开源）；发布动作/规则在业务层 |
| 开发者面 intent.*（产候选语义） | S3 起 | MCP/Intent API |
| **需求情报台 / 需求景气指数 / 信誉档案 / 权益分成闭环 / 撮合运营** | **业务层二期立项（S3 后）** | 反向检查 C12/C22 排期标注：随业务层立项必做，不随撮合上线裸奔 |

## 二、意图系统（业务层产品面）

> 核心层界定：意图作为**记忆类型**（时效、可交易、需确认）留在核心数据模型与接收管道（intent_details 表、状态机位）；本档的**面板/确认链交互/时效运营是业务层产品**。

### 2.1 定义与双入口

意图 = 唯一"有时效、可交易、需确认"的记忆——"未来的事"。**双入口**：用户主动声明（直接生效，可见性自选）；Agent 观察捕捉（**只能产候选**，默认仅自己可见，确认卡片后才可能被发现）——Agent 永远不能替用户"有意图"。组织同构：员工观察 → 部门负责人确认 → Admin 批准（审批人是角色规则数据）。**全网意图确认链只有一条。**

### 2.2 意图面板

三个页签（生效中/已过期/已完成）；**三旋钮**：有效期（一周/一月/直到关闭）、可见性滑杆（仅自己 → 脱敏画像可检索 → 完全公开，每一档是一次视野变更）、期望回应（要方案/直接聊/只收信息不打扰）；机会收件箱与完成记录（业务层承载，核心层只提供状态与可见性变更入口）。

### 2.3 时效推理与配额口径（反向检查 G3 裁定）

有效期到期 → 自动转"已过期" → 归档退出发现索引（血缘下游级联撤下）→ 进遗忘管道。**配额口径全网统一逐字表述：意图本体永远免费、不限量保存；配额限制的是"生效中意图进入发现网络的位数"——免费档 3 个发现位，个人 Pro 不限**（《运营推广策略》§1.3 同源；数字为提案值，随计费评审回填）。

## 三、认知简报（业务层产品）

> 归属界定：简报 = 业务层对核心层 search 的定时消费（栏目选取器族即参数化 search）+ 渲染送达。核心层零简报语义。

**简报不是推送，是分身每天来见你**——五个知晓场景里唯一主动发生的地方。两份刊物：晨报（30 秒"该想起的"，3-5 条每条一句话）、周刊（自我认知的镜子：画像更新/变化轨迹/月度唤起/体检清单）。

```
晨报 · 9月21日          你的分身
【该想起的】三年前的今天，你和林老师聊到想一起做播客——还没开始
            你上周答应客户发的方案，明天是第三天
【你自己没意识到的】这个月你提到"记忆"17 次，上个月只有 3 次
【与你相关】2 条新情报与你"Agent 记忆项目"的意图相关
【你的分身替你读了】今天替你读了 34 条行业动态，3 条你会想知道
```

- 五栏目精确对应五个知晓场景；**"你自己没意识到的"是杀手栏目**——伦理红线：只做温和观察，不做心理评判；
- **简报伦理落点（brief.select 硬编码约束，非参数可调）**："你自己没意识到的"栏目的候选过滤规则为常量数据而非 evolution_params 可调参数——健康/心理状态推断类、亲密关系推断类原子**结构性排除**出该栏目候选（《02_产品设计》§11.3），演化闭环不得触碰此规则（禁区②的具象化）；
- 冷启动：Day 0 初识对话（10 分钟结构化对话产首批 S1 记忆）→ Day 1 第一份晨报的仪式感（"第一天，我记住了你的 7 件事"）→ 每日必达，**宁可短不可断**（心跳机制）；
- 信任机制内嵌：每条可溯源（点开直达出处）、可纠错（长按当场修正）、可反馈（1 秒训练分身）。

## 四、查询即网络的业务面（撮合/发布/情报）

网络不是子系统，是核心层 search 的对外延伸——业务层只做三件事：**发布动作**（视野变更）、**解锁动作**（授权桥接）、**消费动作**（参数化 search）。

| 搜索面 | 业务层角色 |
|---|---|
| 搜自己域内 | 分身空间/记忆中枢两张产品皮 |
| 搜他人 | 撮合检索（公开层 + **目的闸**：查询者声明目的，发布者允许目的集匹配——约束 16）、定向请求 |
| 搜公共信息 | 代理阅读运营（采集回灌 add）、情报流订阅、景气指数 |

**发布管道（业务侧动作链）**：域记忆 → 生成草稿（核心层 l4.abstract，域内可见）→ 分面标注（业务语义归业务层）→ 选公开层级 → 一次性发布授权（域级规则，默认最保守档）→ 事后审阅/修改/否决 + 72h 无痕撤回窗。**对外表述纪律：'自动生成草稿、经你确认发布'——不得表述为'自动公开'**（反向检查 C24）。

**撮合用户体验**：猎头 search 到"某大厂 5 年后端，在看机会"（L4，目的匹配通过）→ 发起请求（add 事件）→ 用户机会收件箱（业务层视图）→ 相互解锁（视野变更动作）→ 标记成交/不合适（add 履约事件）。**撮合无撮合引擎专属 API——检索即撮合的入口。**

**1 + 1 双边激活**：发布需求（想被找到）时，供给自动生成抽象草稿、经确认进入公开层——每个新成员同时充实网络两端（结构内建，运营零动作）。
