# ADR-002 三层两仓开源边界（_03_tech_stack）

> 状态：accepted　日期：2026-09-27（继承自文档族 A14 v2 / 产品 ADR 21 / 业务决策 X1）

## 背景

开源边界是产品承诺（"关于自己的知晓"可被任何人审计；网络效应产物云端独占），需要物理载体防止边界漂移。

## 决策

- `metamemory`（本仓，开源）= **框架层 + 核心层**两包同仓发布：`metamemory_framework`（编排/契约/容器运行时/Store 槽位/防腐层，零业务）+ `metamemory`（收发协议本体：add/search/context/manage + VisionArbiter + 审计/计量横切）；
- `metamemory-x`（独立闭源仓）= 业务层增值产品（意图面板/简报/L4 发布/撮合/情报/信誉/权益），**import 单向 x → core(add/search 门面) → framework**，import-linter 四重规则 CI 阻断；
- 框架表与核心表分离迁移。

## 理由

- 域主权能力在开源两层内完整可行（lite 档本地全闭环）；网络资产（撮合/情报/信誉/指数）云端独占是商业模式（运营策略 §3.2）；
- 框架零业务独立演进/复用（A13 职责封闭集合 + 负空间）。

## 备选方案

| 方案 | 未选原因 |
|---|---|
| 单体同项目 | 开源边界无法技术强制，靠纪律必然漂移（ADR 16 的反面） |
| 三层三仓全拆 | 框架与核心耦合发布节奏，起步期拆仓管理成本 > 收益 |

## 后果

- 正面：边界=CI 规则；lite 档开源用户 `pip install` 即得协议实现；
- 负面/代价：双包版本协同（框架语义化版本 + 核心跟随）；业务表与核心表迁移分轨；
- 对 _04 的影响：分层架构图按两包四模块域绘制（见 _04/01）。
