# ADR-005 数据契约：版本化 JSON 文档 + JSONPath 映射 + 合同测试（_03_tech_stack）

> 状态：accepted　日期：2026-09-27（继承自框架 A6 / 核心选型 #18）

## 背景

管道步骤与模型之间如果共享类型对象/import 上游类型，上游换模型或改 schema 将引发下游级联修改；数据契约是"模块只依赖契约不依赖实现"的载体。

## 决策

1. 步骤/模型间传**版本化数据文档**（JSON，落 task_steps 检查点），不传对象、不 import 类型；
2. 每步骤以字段映射声明"我需要什么、从哪里取"（JSONPath，从 input/context map 抽取）与"我产出什么、写到哪"（拍平映射写回 output map）；
3. 判定型步骤 output 必带 `confidence`（0–1）与可选 `abstain_reason`（软信号契约 A14-⑤/ADR-003；CI 断言强制）；
4. 契约进 CI：黄金样本回放 + 字段断言（合同测试），映射失效阻断发布；契约破坏性变更 = 新契约版本 + 新步骤版本（禁原地改）。

## 理由

- 上游换模型/改 schema = 改一行映射配置，下游零改动；
- LLM prompt 输入绑定同走映射配置，prompt 版本可回放（llm_calls 幂等键 = node_id+input_hash+prompt_version）。

## 备选方案

| 方案 | 未选原因 |
|---|---|
| 共享强类型对象 | import 耦合，上游变更级联下游 |
| 约定俗成字段名（无映射配置） | 无 CI 可校验点，漂移不可控 |

## 后果

- 正面：模块边界=数据契约；合同测试成为发布门禁；
- 负面/代价：映射配置是运行时字符串路径，拼写错误需靠配对校验+黄金样本兜住；调试时多一层拍平/提取间接性；
- 对 _04/_06 的影响：契约引擎（contract/mapper+assertor）为框架模块；_06/02 按契约定义内部接口。
