# ADR-003 abstain 为一等处置原语（_03_tech_stack）

> 状态：accepted　日期：2026-09-27（继承自框架 A15 / 设计原理约束 15 / 产品 ADR 20 / 核心选型 #26）

## 背景

Turing 1936：形式上存在不可判定的判定问题——任何全自动判定必有覆盖不到的输入。"默认值兜底 = 静默处理"是治理与质量归因的毒药：判不了被混同于成功，上游失灵无从观测。

## 决策

1. 异常策略引擎新增 `Undecidable` 错误型 → action=`abstain`：节点置 `abstained` + 写 `pipeline_review_queue`（引用+原因码+待裁状态）+ 指标 `fw_abstain_total{step,reason}`；原因码必填、禁空串/禁 "unknown"；
2. 图编译期校验（第五关前置）：switch 的 default 与条件边全未激活的兜底路径**不得直接进入成功终态**，必须显式指向 review/abstain/dead_letter 类节点；
3. 业务四态路由（提取/折叠/留原文/**abstain**）与实体统一第三级（match/new/abstain，弃权=新建）遵循同一原语；
4. 禁配（CI 拒收）：以 reply/retry 处置 Undecidable；default 直连成功终态；abstain_reason 缺省。

## 理由

- "判不了"是合法结论不是失败路径（冲突三分法中真矛盾挂人裁、score 四态、实体消解三态的公共语义）；
- 弃权率是上游质量归因必看指标：弃权率突升 = 前置级联失灵或输入分布漂移（设计原理 §7.1 失效信号）。

## 备选方案

| 方案 | 未选原因 |
|---|---|
| 仅死信兜底 | 把"判不了"混同"出错"，质量归因失灵 |
| 默认值兜底 | 静默处理，违反约束 15，CI 拒收 |

## 后果

- 正面：全框架零静默兜底；人裁队列成为产品质量信号的显式汇口；
- 负面/代价：每条判定链需设计 abstain 出口与复核 SLA；复核队列积压需监控；
- 对 _04/_06 的影响：异常策略表、图约束、score.route/实体统一契约均含 abstain 分支（见 _06/02）。
