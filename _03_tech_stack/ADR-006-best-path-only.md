# ADR-006 单一最佳路径：禁止质量降级链（_03_tech_stack）

> 状态：accepted　日期：2026-09-27（用户当场指令，优先于既有文档与 ADR-001~005 的相关表述）

## 背景

骨架期为实现"lite 档本地全闭环"引入了多条质量降级路径：`extract_lite` 规则提取作为强模型提取的 fallback、推理双通道 Embedded/Gateway 自动互切、rerank 可降档。用户裁定：**降级路径是后续才考虑的事情，现在只做最佳效果**。

## 决策

1. **删除 `extract_lite`**：深提取只有强模型网关一条路径；DependencyError → 重试/死信（显式失败），ContractViolation → 复核，**不再回退到规则提取**；
2. **删除推理双通道自动降级**：`InferenceProvider` = 唯一 `GatewayProvider`（OpenAI 兼容 HTTP 网关，stdlib urllib 实现，任意 OpenAI/vLLM/Ollama/Ark 兼容端点可接）；未配置端点 = 启动期显式配置错误，运行期网络故障 = DependencyError（重试/死信），**不静默切本地小模型**；
3. **删除 `degraded`/rerank 降档语义**：search 响应不再携带 degraded 字段；精排后续作为最佳路径的组成部分直接实现；
4. 异常策略引擎的 `fallback` **动作类型保留**（框架原语，供基础设施用途），但业务流程图不得把"质量更低的实现"声明为 fallback 目标（flows CI 语义约束）；
5. Store 槽位的部署降级矩阵（ADR-004）属于**基础设施可用性**（Redis 缺席→内存缓存），不是质量降级——本次不动，其裁撤与否留待用户后续裁定。

## 理由

- 降级路径让"最佳效果"不可观测：评测无法区分"管道能力"与"降级实现的能力"（首轮评测已暴露 extract_lite 掩盖真实提取质量的问题）；
- 显式失败（重试/复核/死信）符合 ADR-003 精神：静默降质 = 另一种静默处理。

## 备选方案

| 方案 | 未选原因 |
|---|---|
| 保留降级链 + 评测分档报告 | 用户明确要求先只做最佳效果 |
| 同时裁撤 ADR-004 槽位降级矩阵 | 基础设施可用性与质量降级是两件事，lite 部署依赖它 |

## 后果

- 正面：系统只有一条质量路径，评测数字即系统真实能力；失败显式可观测；
- 负面/代价：未配置推理网关时系统不能完成深提取（这是诚实的代价）；后续引入边缘部署时需重新立项降级设计（届时另立 ADR）；
- 影响：flows/contracts 错误策略去除 fallback；_06 接口描述同步；eval 的路由套件改用**评测替身 Provider**（测试工件，非系统路径）。
